# Бэкапы, журнал удалений и место на телефоне

5 ноября 2026. Пункты 1 и 2 из разбора приложения.

## Ночной бэкап

- Таймер Yandex Cloud `gymapp-nightly-backup` каждый день в 03:00 по Москве
  (`0 0 ? * * *`, UTC) вызывает функцию `d4ehbqgul5keq1hehqvb`. Функция узнаёт событие
  таймера по полю `messages`, которое кладёт платформа; HTTP-запрос его подставить не может.
- Для каждого владельца из `TELEGRAM_USER_MAP` читаются строки всех gym-таблиц как есть:
  упражнения, алиасы, тренировки, группы, подходы, кардио и журнал удалений.
  Файл `gymapp/<user_id>/<YYYY-MM-DD>.json.gz` ложится в закрытый бакет `gymapp-kpg-backups`
  (переменная функции `BACKUP_BUCKET`). Формат `gymapp-raw-backup-v1`: `tables` с
  исходными строками и `counts` для быстрой сверки.
- Повтор в тот же день перезаписывает файл дня. Старые файлы не удаляются: в сжатом виде
  это сотни килобайт в день.
- Ошибка бэкапа видна в логах функции как `Nightly backup failed`.

Запустить вручную (только чтение базы и запись в бакет бэкапов):

```bash
yc serverless function invoke d4ehbqgul5keq1hehqvb -d '{"messages":[{"event_metadata":{"event_type":"yandex.cloud.events.serverless.triggers.TimerMessage"}}]}'
```

Скачать: `yc storage s3api get-object --bucket gymapp-kpg-backups --key gymapp/<user_id>/<дата>.json.gz <файл>`.

## Журнал удалений

Миграция `supabase/migrations/20261105200000_gym_deletion_journal.sql`: перед удалением
любой строки gym-таблиц её полная копия ложится в `public.gym_deleted_rows`. Это работает
при любом пути удаления: через API, вручную, каскадом от тренировки или пользователя.
Доступ к журналу есть только у сервисной роли; запись идёт через `SECURITY DEFINER`, поэтому
не зависит от прав того, кто удаляет.

Вернуть удалённую тренировку: найти её id и выполнить
[`scripts/restore_deleted_session.sql`](../scripts/restore_deleted_session.sql), подставив id.
Скрипт возвращает тренировку, группы, подходы и кардио из того же удаления; повторный
запуск откатывается целиком и ничего не задваивает. Это проверено в
`scripts/tests/deletionJournal.test.mjs`.

## Место на телефоне

- Старые общие копии истории (`gym_global_history_cache`) и каталога (`gym_exercises_cache`)
  больше не пишутся и стираются при запуске: у каждой есть копия владельца, которую и читает
  приложение. Список `gym_finished_local` стирается, когда есть список владельца.
  На 20.10 одна история занимала 375 тыс. символов, теперь она хранится один раз.
- Очередь подходов, черновик, отметка тренировки и таймер пишутся через
  `setItemFreeingSpace`: если места нет, по одной стираются копии для чтения — старые копии,
  аналитика, истории упражнений, в последнюю очередь история — пока запись не поместится.
  Каталог и очередь не стираются никогда.
- Приложение один раз просит браузер о постоянном хранилище (`navigator.storage.persist`).
