## Хранение и интерфейс

GIF загружаются в существующий Yandex Object Storage bucket `gymapp-kpg-photos`,
префикс `exercises/catalogue/20261104/`. Имя файла — SHA-256 содержимого;
тип `image/gif`, кэширование immutable. Публичный GET каждого объекта проверяется
сравнением SHA-256 до изменения ссылок в базе.

Просмотр техники использует `object-contain`, чтобы анимация показывалась целиком.
Дополнительное фото открывается отдельным раскрывающимся блоком. Тип `Exercise`
получил поле `imageUrl2`, уже возвращаемое существующим backend.

Источники и пометки соответствия сохранены в manifest; водяные знаки не удалялись.
Новая лицензия на сторонние материалы не приобреталась; запрос пользователя
на публикацию зафиксирован в этой беседе, отдельная лицензия не подтверждалась.

## Резервирование и обновление

До записи создана приватная резервная копия всех 56 таблиц/представлений,
доступных через PostgREST: 15 123 строки, gzip JSONL и manifest с контрольными
суммами. Расположение вне публичного Git:
`D:\Projects\GymApp-backups\exercise-media-20261104\production-apply\`.

План сравнивается со снимком и свежей строкой. PATCH ограничен владельцем,
ID и прежними значениями ссылок; меняются только `image_url` и при необходимости
`image_url_2`. После каждого изменения сохраняются прежние и новые значения
для обратного обновления. Проверка read-only сверяет остальные поля карточек
и прежние строки истории, сессий, групп, кардио и алиасов.
