# Быстрая история, локальная аналитика и запуск без сети

20.10.2026. Опубликовано после подтверждения пользователя: миграция Supabase,
backend Яндекс Облака и фронтенд GitHub Pages. Результаты проверки рабочего
сайта приведены в конце документа. UI-коммит `b37a38d` вошёл в этот релиз.

## Что изменилось

1. **Аналитика вычисляется из истории на телефоне.** Периоды 7 / 14 / 28 дней
   доступны сразу, даже если этот период прежде не открывали. Учитывается
   завершённая тренировка, ещё ожидающая отправки, и правки сохранённых подходов.
   Используются сохранённый итоговый вес, рабочие подходы и признак включения
   в тоннаж. Разминка и исключённые подходы не добавляются. Формулы и округление
   проверены против Python API и общего контракта HealthOS `workload-trend-v1`.
   Старая копия без необходимых признаков продолжает использовать прежнюю
   сохранённую аналитику / API до первого успешного обновления истории.
2. **Приложение открывается после закрытия без сети.** Service Worker сохраняет
   публичные HTML / JS / CSS / иконки приложения. Локальная копия привязана
   к прежнему владельцу HealthOS; истёкшая сессия не задерживает её показ.
   Маркер владельца не даёт доступа к API: сетевые операции по-прежнему требуют
   действительного Supabase-токена или подписанных данных Telegram.
   Явный выход закрывает локальный доступ, сохраняя очередь и черновик.
3. **Правки истории не ждут ответа сервера.** Вес, повторения, отдых, удаление
   подхода и удаление сохранённой тренировки сначала попадают в существующую
   долговечную очередь и сразу отображаются. Повторная правка во время запроса
   сохраняет тот же идентификатор и отправляет последнее состояние.
   Удаление подхода не меняет сообщённую пользователем длительность `≈60м`.
4. **Графики вынесены из кода, необходимого для открытия приложения.** Основной
   интерфейс загружается отдельно; модуль графика подгружается в фоне. Ошибка
   загрузки графика не закрывает тренировку или числовые показатели.
5. **Фоновая синхронизация передаёт изменившиеся тренировки.** Один запрос
   возвращает полный список идентификаторов с версиями и тела только изменённых
   тренировок. Отсутствующие в списке записи удаляются из локальной копии.
   Версия хранится вместе с соответствующей тренировкой в одной записи кеша.

Новая версия приложения устанавливается в фоне и предлагает кнопку обновления.
В открытом приложении кнопка недоступна во время тренировки или при непустой
очереди; установка не перезапускает работающий таймер. Кеши других приложений
не удаляются. Обновление при следующем холодном запуске использует совместимый
формат прежних очереди и черновика.

Отдельный SQL: `supabase/migrations/20261020194920_gym_journal_snapshot_v1.sql`.
Добавляет только функцию чтения `public.gym_journal_snapshot_v1(uuid, jsonb)`.
Она получает согласованный снимок одним SQL-запросом и вычисляет версии по
содержимому сессии, групп, подходов, кардио и использованных упражнений.
Права выполнения есть только у `service_role`; функция `SECURITY INVOKER`,
`STABLE`, с пустым `search_path`. Владелец берётся из проверенной авторизации
backend, а не из тела запроса клиента.

Таблицы, данные, RLS, существующие представления и интеграции HealthOS
не меняются. Нет триггеров, массового обновления или повторного импорта 12.10.
Снимок всё ещё читает и хеширует историю на сервере; оптимизация уменьшает
количество сетевых запросов и передаваемые данные, а не устраняет чтение БД.
Без миграции новый backend возвращает полную историю как совместимый fallback.
При временной ошибке сохраняется последняя успешная локальная копия.

Прокси `D:\Projects\HealthOS\supabase\functions\gymapp-auth-proxy\index.ts`
проверен: существующий маршрут пропускает новый `POST /api/journal_sync`.
Изменение и публикация прокси не нужны. Устаревший код Google Sheets не менялся;
чужие локальные правки не входят в коммит этой работы.

  за **49–68 мс**, аналитика за **33–66 мс** при удерживаемом ответе API.
  Общий период, сводка, повторение тренировки и сохранность очереди проверены.

- Правка истории стала видна за **62–86 мс** при задержанном запросе.
  Проверены повторная правка во время отправки, HTTP 503, офлайн-перезагрузка,
  последующая отправка последнего состояния, оба удаления и отсутствие дублей.
  При неизменной истории тела тренировок не передавались; после правки
  одного подхода вернулась одна тренировка.
- Повторение, замена после частичного выполнения, отдельные подходы и отдых,
  пятичасовой перерыв и прежние единицы веса / идентификаторы очереди прошли

- SQL выполнен только в PGlite: принадлежность владельцу, изменение одного
  подхода, метаданных упражнения, удаление, неизменность прежнего представления
  и запрет выполнения функции браузерными ролями проверены.
- Ошибок JavaScript не обнаружено. Механическая проверка изменённого UI
  не выявила замечаний; мобильные и широкие экраны просмотрены.
