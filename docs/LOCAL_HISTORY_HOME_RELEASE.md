# Локальная история и главная страница

20.10.2026. Статус: реализация и проверки завершены локально; новая сборка ещё не опубликована. Рабочие данные не изменялись.

## Результат

- История, сводка тренеру и уже загруженные периоды аналитики открываются из памяти устройства сразу. Запрос к API обновляет интерфейс в фоне.
- Сохранённая история не стирается при сетевой ошибке, тайм-ауте или некорректном ответе. Корректный пустой ответ сервера обновляет копию до пустой истории.
- Одновременные переходы между главной, историей и сводкой используют один запрос истории. Повторный вход на экран не запускает такой же запрос заново.
- Данные обновляются в фоне при запуске приложения, возвращении связи/вкладки и после отправки очереди. Для фоновых повторов действует интервал свежести пять минут; кнопка обновления позволяет запросить данные сразу. Неудачные автоматические попытки имеют паузу 30 секунд.
- Добавлены время последнего обновления, состояние локальной копии и ручное обновление. Ошибка сохранения при нехватке места показывается отдельно; старая дисковая копия и очередь не удаляются.
- Главная содержит начало/повторение тренировки и заметные переходы в аналитику, сводку для Паши и справочник. Нижняя навигация «Главная / История / Аналитика» доступна и во время тренировки. При наличии очереди в ней появляется отдельная кнопка; плавающий индикатор больше не закрывает поля.
- Кнопка копирования сводки находится выше нижней навигации с учётом safe area. Существующие черновики, таймер и очередь сохраняются при переходах.

## Хранение и совместимость

Используется существующий `localStorage`, новые зависимости и Service Worker не добавлялись. Ключи новых копий: `gym_read_cache_v1:<владелец>:<данные>`. Хранятся журнал, каталог, истории упражнений и отдельные периоды аналитики. Владелец определяется текущей сессией Supabase Auth либо Telegram; это разделение локальных данных, не способ авторизации API. Поздние ответы для предыдущего аккаунта не записываются в копию текущего.

Существующая очередь `gym_offline_queue_v2`, клиентские идентификаторы, единицы веса старых черновиков и правила отправки не изменены. Локальные завершённые занятия учитываются до подтверждения всей очереди; ответ, начатый до её подтверждения, не вытесняет более свежие данные. Сохранены совместимые записи в прежние ключи журнала и завершённых тренировок.

При первом запуске этой версии потребуется одна успешная загрузка истории и каталога: прежние серверные копии без указания владельца не показываются под новым аккаунтом. Старые ключи, черновик и очередь не удаляются. После загрузки новая копия доступна при следующих открытиях. На iPhone следует обновить приложение без очистки данных сайта.

API, backend, Supabase-прокси, схема и представления HealthOS не менялись. Legacy Google Sheets не используется. Чужие локальные изменения в `README.md`, `bot.py`, `front/vite.config.ts`, `google_sheets.py`, `render.yaml` и пользовательский `docs/DEPLOYMENT_MAP.md` сохранены.

- До изменения: при задержке API 5 секунд экран истории с уже сохранёнными данными появился через **5590 мс**. После изменения на том же тестовом наборе: **51 мс desktop / 45 мс mobile**, пока ответ API ещё ожидался. Сохранённая аналитика: **39 / 56 мс**. - Дополнительно выполнен один авторизованный **GET** рабочей истории: 61 тренировка и 1408 подходов; JSON 332269 байт, эквивалент одной строки UTF-16 в localStorage — 649910 байт. Вместе с временно сохраняемым прежним ключом это около 1,3 МБ для журнала; каталог и аналитика занимают дополнительное место.
- С этой настоящей копией из 61 тренировки мобильный Chromium открыл историю за **122 мс**, не получив ответ API. Проверка выполнялась на локальной production-сборке; записей в рабочую базу не было.

- Снимки главной и аналитики просмотрены на двух размерах; горизонтального переполнения не обнаружено. Механическая проверка изменённых UI-файлов Impeccable не обнаружила замечаний.
